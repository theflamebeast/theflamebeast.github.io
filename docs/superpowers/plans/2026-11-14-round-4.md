## Owner decisions, 2026-11-14

1. **The next-project cover always shows**, on every device, instead of wiping in on hover or focus.
2. **FlameBurst's outbound link loses "(on hiatus)"**: the site itself says so. It reads `flameburst.net`.
3. **Stashout gets a `stashout.io` button.** The domain is live and serves a "Coming Soon" page
   (checked 2026-11-14: HTTP 200 on `stashout.io`, `www.` redirects to it). This replaces the first
   spec's "No Play link yet", which was true on 2026-11-10 when the domain did not resolve.
   *My choice, not specified:* the label is plain `stashout.io`, with no "(coming soon)", on the same
   reasoning as 2; and it goes in the project's `links` list, not in `liveUrl`, because `liveUrl`
   renders a button labelled "Play" (`[slug].astro`) and the game cannot be played yet. When it can,
   set `liveUrl` instead and drop the link.
4. **Both Architecture buttons read "Architecture"** (Stashout's "Architecture tour" is renamed).
   *My choice:* the shorter label, since the two point at different things (a showcase repo, a write-up
   page) and the label only says what kind of thing it is.

5. **The ink cover is removed completely**, both the page-to-page transition and the once-per-session
   first-visit intro (they are one machine). Pages change with an **instant swap**: Astro's
   `ClientRouter` stays (no page flash, scroll resets, `onPage` unchanged), with no cover and no
   animation of any kind. The router's own crossfade must stay off (see R9, step 4).

Link order on both case studies: the project's own site first, then Architecture.
